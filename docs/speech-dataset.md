# Корпус речи: диктовка и встречи

## Сбор

В Android: **Аудиозаметки → Долгая диктовка для обучения → Записать диктовку**.
Явно запущенный foreground-сервис сохраняет PCM16 mono 16 кГц частями по 5 минут,
продолжает запись при выключенном экране и заканчивает её кнопкой/уведомлением.
Текст на телефоне не распознаётся; закрытие экрана управления не выключает запись.
После остановки сохраняется последняя короткая часть. Обновления откладываются,
пока запись активна. Предельный локальный объём корпуса — 2 ГБ; заполнение
останавливает запись с сообщением. Синхронизация использует существующий HTTPS Hub.

На компьютере: раздел **Запись для обучения** в Hub. Выберите микрофон, звук
приложений/встречи или оба источника. Нажмите **Начать запись**; затем
**Остановить и сохранить**. macOS helper на CoreAudio и AVAudioEngine требует macOS 15+
и запрашивает системные разрешения при первом пользовательском запуске.
Микрофон и системный звук сохраняются отдельными дорожками. Видео не сохраняется.
Само открытие раздела не начинает захват. По чтению статуса также ничего не запускается.

Корпус находится в каталоге состояния Hub: `asr-dataset/audio` и
`asr-dataset/samples.sqlite`. Он не становится заметками или общей памятью агента.

Обычные голосовые команды можно дополнительно собирать в режимах «Только
исправленные» / «Все реплики» в **Модели → Датасет распознавания речи**. По умолчанию
этот дополнительный сбор выключен. У команд, записанных в этом режиме, есть
кнопка исправления. Исправление сохраняет метку, не повторяя команду.
Недавние кандидаты для исправления ограничены 12 репликами и 24 часами.

## Разметка и обучение

После записи в Hub нажмите **Разрезать и распознать большой моделью**.
Используется faster-whisper `large-v3`; при первом запуске скачиваются веса.
Большая модель работает на компьютере, а не на телефоне.
Она возвращает временные границы фраз. Оригиналы сохраняются, а отрезки
сохраняются отдельно; `transcripts.jsonl` содержит полную предварительную разметку.
Отрезки с низкой уверенностью, длиннее 20 секунд, числами или латинскими словами
не попадают в автоматический обучающий набор. Такие метки требуют проверки:
алфавит T-one — русский, поэтому нельзя молча удалить произнесённые числа/имена.

Разметка большой модели — **псевдометки**, а не подтверждённый человеком текст.
Она может ошибаться, особенно при шуме или одновременной речи. Для измерения
реальной точности нужны отдельно проверенные записи. WER на псевдометках показывает
совпадение с разметчиком. Сессии и одинаковые исходные записи не смешиваются
между train и validation. Для обоих наборов нужны минимум две разные сессии.

Кнопка **Дообучить T-one по разметке** запускает отдельную задачу на компьютере.
Сохраняются исходный результат проверки, результат после обучения и checkpoint.
Полученный checkpoint затем нужно экспортировать в совместимый потоковый ONNX,
проверить на отложенных реальных записях и Android runtime. Эта версия не подменяет
рабочие Android ASR-веса автоматически.

CLI альтернативы:

```sh
python tools/speech_teacher.py --state /path/to/hub-state/asr-dataset --output /path/to/new-dataset
python tools/train_speech_model.py --dataset /path/to/new-dataset --output /path/to/new-model --allow-pseudo-labels
python backend/speech_dataset.py --state /path/to/hub-state/asr-dataset export /path/to/human-reviewed-export
```

## Среды и воспроизведение

Системный Hub не получает тяжёлые ML-зависимости. Разметчик и обучение используют
отдельные виртуальные среды. При необходимости задайте в конфигурации
`speech_teacher_python`, `speech_training_python` и `speech_capture_helper`.
Зависимости разметчика: `tools/speech-training-requirements.txt`.

Обучение использует официальный wrapper T-one, зафиксированный на
`3c5b6c015038173840e62cea99e10cdb1c759116`. Для него рекомендуется Python 3.12
(старый KenLM не компилируется на Python 3.13 без дополнительных изменений).
Проверенный набор: torch/torchaudio 2.7.1, transformers 4.57.6, pyarrow 20.0.0.
PyArrow 26 требует NumPy 2, тогда как зависимости CTC decoder здесь выбирают
NumPy 1.26; этот конфликт обходится отдельной средой и pin PyArrow.

```sh
python3 tools/build_speech_capture.py
uv venv --python 3.12 /path/to/training-venv
uv pip install --python /path/to/training-venv/bin/python 'torch==2.7.1' 'torchaudio==2.7.1' 'pyarrow==20.0.0' 'tone[finetune] @ git+https://github.com/voicekit-team/T-one.git@3c5b6c015038173840e62cea99e10cdb1c759116' 'scipy==1.16.2' 'soundfile==0.13.1' 'jiwer==4.0.0'
```

Основные источники: [T-one и официальный пример дообучения](https://github.com/voicekit-team/T-one/blob/main/examples/finetune_example.ipynb),
[faster-whisper](https://github.com/SYSTRAN/faster-whisper),
[CoreAudio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps).

## Coucou и исходный звук

В локальной сборке Coucou 0.2.3.3 есть отдельная вкладка «Аудиозахват» и стандартный
маскот Mochi. Его цвет выбирается в Settings → Active pills: точка рядом с «Аудиозахват». Меню Coucou → Аудиозахват открывает управление; запись запускается
кнопкой. Настройка применяется к большому маскоту и миниатюре вкладки.

Mac сохраняет нативный PCM в `.raw.caf` с исходными каналами и частотой: без VAD,
удаления пауз и программного шумоподавления. Системная дорожка записывается как stereo mix, микрофон сохраняется в исходном формате AVAudioEngine, системный звук — в формате CoreAudio tap.
Каждая часть ≈15 секунд. Соседний `.raw.json` хранит формат и SHA256. Оригиналы
лежат в `speech-capture/SESSION/`; недофинализированные `.part.caf` после сбоя
также сохраняются. `.wav` 16кГц mono в корпусе — отдельная производная для ASR.
Настройки обработки самого устройства/ОС приложение обходить не может.

Флажок «Транскрибация» запускает независимый Whisper-base CPU/int8
после первой части; при первом использовании скачиваются веса. Он обрабатывает
полные завершённые части, поэтому это предварительный текст с задержкой минимум
≈15 секунд плюс время распознавания. `live-transcripts.jsonl` сохраняет метки
отдельно, не меняя сырьё и не подтверждая текст человеком. Ошибка разметчика
не останавливает запись. Большая large-v3 остаётся для последующей разметки.

Coucou использует существующий приватный capability URL локального Ollama.
Разрешён только loopback и модельный API + управление захватом, без общего
доступа к данным Hub. Никаких новых ключей в Coucou не сохраняется.

Для CoreAudio taps нет публичного API предварительной проверки разрешения: доступ подтверждается при запуске аудиопотока. Микрофон проверяется отдельным публичным API. Разрешение на экран не запрашивается и не проверяется.

В Coucou параметры источников и транскрибации перенесены в Settings → Active pills → Аудиозахват. На главной карточке — круглая кнопка: красный кружок запускает запись, квадрат останавливает. Текст показывает временное окно последних 15 секунд распознанного аудио, с учётом задержки модели.

При отказе macOS Coucou показывает кнопку «Разрешить в macOS», открывающую нужный раздел Privacy & Security. В Settings → Active pills → Аудиозахват также есть ссылки для микрофона и записи системного аудио. Разрешение выдаётся вручную в macOS; после него повторите запуск записи.

Рядом с кнопкой записи Coucou показывает 16 полосок измеренного уровня PCM и отдельную пульсирующую точку REC с длительностью записи. Уровни обновляются 4 раза в секунду; в тишине полоски опускаются, а REC продолжает показывать активную запись. Это измеритель громкости, не частотный FFT-спектр.

## Записи и полные транскрипты

Кнопка «Записи» в Coucou открывает `~/Documents/Аудиозаписи` (путь можно переопределить
полем `recordings_directory` в конфигурации Hub). Для каждой сессии создаются файлы
`YYYY-MM-DD_HH-MM-SS_SESSION_микрофон.wav` и `…_звук-Mac.wav`, с одноимёнными `.txt`.
WAV сохраняет нативную частоту/каналы/PCM, без шумоподавления; исходные CAF-части
также остаются в частном каталоге захвата. Примерные имена относятся ко времени
начала записи. Полные WAV появляются после остановки и объединения частей.

Во время сбора Whisper-base обрабатывает снимки растущего ASR-WAV каждые примерно
4 секунды. В UI есть возраст предварительного текста; CPU-обработка добавляет задержку.
TXT обновляется по мере распознавания и явно помечен как предварительный. После
остановки Whisper-small распознаёт целые файлы, сохраняет полный TXT и убирает
предварительную пометку. Дополнительная большая модель для обучающего корпуса
по-прежнему запускается отдельно. Запись сырья независима от этих моделей.

Индикатор читает последние 100 мс уже записанного PCM, обновляется примерно за
50–150 мс и показывает отдельно «Мик» и «Mac». Это уровень звука, не спектр частот.
Кнопка транскрибации управляет live-режимом; полные TXT после остановки создаются
автоматически. Модели работают локально, аудио не отправляется сторонним сервисам.

### Язык транскрипции

Live и полный ASR сохраняют русский и английский без перевода. На каждом окне
декодирования заново выбирается язык (`language=None`, `multilingual=True`,
`task=transcribe`), поэтому русская проверка микрофона в начале не заставляет
распознавать всё последующее английское интервью на русском. Выбор сейчас
ограничен ru/en: unrestricted auto может принять английский с греческим акцентом
за греческий. Другие языки требуют расширения `LANGUAGES` в
`backend/speech_recognition.py` и отдельной проверки. Модели остаются прежними,
base/small CPU int8; дополнительные веса не скачиваются.

В `.asr.json`, `.timestamps.json`, `.segments.jsonl` и live-журнале поле
`recognition` хранит режим выбора, допустимые языки и первоначальную оценку языка.
Она не является языком всех слов записи; вероятности после фильтрации не повышаются.
Редактор не переводит английские фразы в русский. Старые транскрипты автоматически
не заменяются: для явно выбранной сессии используй `--retime` с резервным
копированием старых текстов. Исходное аудио и интервалы других записей не меняются.

## Эхоподавление колонок

Когда включены микрофон и звук Mac, live- и полная транскрибация используют
микрофон с адаптивным эхоподавлением SpeexDSP. Системная дорожка служит
опорным сигналом; оба стереоканала обрабатываются отдельно, без сведения в моно.
Корреляция каждого канала компенсирует до ±1 секунды рассогласования начала
захвата. Для длинных записей задержка переоценивается каждые 15 секунд,
с контекстом адаптации 2 секунды. Каждый снимок сначала обучает фильтр, затем
проходит выходную обработку с подавлением остаточного эха. При одновременной
ближней речи дополнительное подавление ослабляется; задержка подавителя
компенсируется, длительность и позиция речи сохраняются.
При тишине/отсутствии опорной дорожки или
недостоверной корреляции микрофон проходит без изменений. Фильтр не включает
ослабление общего шума и AGC. При сильных искажениях колонок/микрофона или
рассогласовании больше секунды полное удаление эха не гарантируется.

Зависимость среды распознавания: `brew install speexdsp` (Linux: системная
`libspeexdsp`). Нестандартный путь задаётся `SPEEXDSP_LIBRARY`.

После остановки рядом с исходными файлами появляется
`…_микрофон-без-эха.wav` (16 кГц mono) с одноимённым полным `.txt`.
TXT исходного микрофона тоже получает текст из очищенного сигнала. Системный
звук распознаётся отдельно. Нативные WAV, CAF и исходные образцы в корпусе
не заменяются и не фильтруются: шумное сырьё для обучения сохраняется.
Запись не зависит от доступности фильтра; ошибка обработки видна как ошибка
транскрибации/финализации.

## Запуск после перезагрузки macOS

`python3 tools/local_stack.py autostart-enable` устанавливает пользовательский
LaunchAgent `local.assistant.stack.login`. При входе в графическую сессию он
однократно запускает уже настроенный локальный стек и Coucou по `coucou_app`.
Новых моделей/приложений не скачивает и запись не включает. Выход из Coucou
не вызывает его повторный запуск в текущей сессии. Журналы —
`~/.local/share/assistant-stack/logs/login-start*.log`.
Отключение: `python3 tools/local_stack.py autostart-disable`; текущие приложения
при этом продолжают работать. Это запуск всего локального стека, отдельный от
переключателя SMAppService в настройках Coucou.

В обработчике v3 после стереофильтра добавлено ограниченное подавление
частотных остатков, сохраняющих фазовую связь с исходным системным звуком.
Оценка строится по самим каналам Mac, а не по разности микрофона и фильтра,
чтобы не принять изменения голоса за эхо. Дополнительное ослабление ограничено
6 дБ в полосе; это не общий шумодав. Независимый от Mac шум не удаляется.
При отсутствии корреляции (например, воспроизведение в наушниках без утечки)
обработка полностью пропускается. Это проверка сигнала, не определение типа
подключённого устройства. Сырьё остаётся без обработки.

## Очистка речи от общего шума

`python3 tools/install_voice_cleanup.py` отдельно устанавливает проверенную по
SHA256 модель RNNoise (`somnolent-hogwash`, upstream commit
`3eee541a283fd3b8f81b85b1748e3b9ccbefa04d`). Автоматических скачиваний во время
записи нет. Обработка использует уже установленный FFmpeg с фильтром `arnndn`.
Если модель не установлена, запись/транскрибация продолжаются без этого этапа;
`archive.json` указывает `voiceCleanup: unavailable`.

После удаления эха микрофон проходит речевой шумодав RNNoise с 10% исходной
дорожки для мягкости, срезом инфраниза ниже 80 Гц и частот выше 7600 Гц. Задержка
RNNoise 10 мс компенсируется с дренированием хвоста, паузы не удаляются.
В папке записей появляется дополнительная пара `…_голос.wav` + `…_голос.txt`.
Исходные нативные WAV/CAF и отдельная версия `…_микрофон-без-эха.wav` сохраняются.
Live- и полная транскрибация микрофона используют речевую версию, в том числе
при записи без системной дорожки. Системный звук не проходит речевой шумодав.

Это улучшение речи, не разделение говорящих: чужая речь или музыка, звучащие
одновременно с голосом, могут частично сохраниться; тихие/необычные звуки голоса
могут ослабляться. Оригиналы нужны для последующей разметки и обучения.
Режим действует на новые ASR-работники без пересборки Coucou и без обновления
нативного модуля захвата/разрешений macOS. Для отключения этапа в среде работника
можно задать `VOICE_CLEANUP_DISABLE=1`.

## Контекстная правка транскрипта

После полного распознавания идёт отдельный текстовый проход через настроенную
локальную Ollama-модель (`providers.ollama`). Фрагменты до 2400 символов получают
по 500 символов соседнего контекста. Модель предлагает короткие исправления
окончаний, опечаток и названий по теме, например «код на котли» → «код на Kotlin».
Новые предложения/факты не дописываются. Для явно сообщённого пользователем
случая «котли» есть дополнительная словарная правка в Kotlin, только если
рядом есть контекст программирования/Android и Kotlin включён в словарь терминов. Перед применением проверяются точное
совпадение и уникальность исходного фрагмента, границы слов, отсутствие
пересечений, сохранение чисел, количества слов и малый размер замены. Это
ограничивает переписывание, но не гарантирует правильность спорного термина.

Основной `… .txt` содержит исправленный вариант, соседний `….asr.txt` —
неизменённый текст распознавателя. `….review.json` хранит модель, SHA256 исходного
текста, предложенные/применённые правки с исходными позициями, отклонённое
количество и ошибки частей. Одинаковый текст в микрофонной, безэковой и речевой
версиях обрабатывается один раз. Эти исправления не являются человеческой
разметкой и не подменяют метки обучающего корпуса.

При ошибке модели соответствующий кусок остаётся исходным, распознавание не
теряется; состояние — `archive.json/textReview.phase: partial`. Прогресс сохраняется
после каждого куска. Повторный текстовый проход без чтения больших WAV:

```sh
python3 tools/recording_finish.py --directory /absolute/path/to/speech-capture/SESSION --review-only
```

Он берёт `.asr.txt` при наличии и повторяет только неготовые части. При изменении
исходного текста, модели, словаря или версии редактора кэш сбрасывается.
Настройки в конфигурации локального стека:

```json
"transcript_review": {
  "enabled": true,
  "model": "qwen3:4b-instruct-2507-q4_K_M",
  "terms": ["Kotlin", "Android", "Gradle", "Jetpack Compose"]
}
```

Без `model` используется `providers.ollama.model`. URL — адрес локальной Ollama;
обработчик принимает только loopback, облачная отправка транскрипта не добавляется.
`enabled: false` отключает правку, сохраняя исходный ASR. Аудио не пересобирается,
live-превью остаётся предварительным текстом ASR; контекстная правка применяется
к полным транскриптам после остановки. Пересборка Coucou не требуется.

## Временные метки и подготовка датасета

Финальный ASR выполняется с `word_timestamps=True`. Слова и сегменты сохраняются
до текстовой правки: интервалы привязаны к началу конкретного аудиофайла,
не к моменту импорта в Hub и не к общему времени двух устройств. У микрофона
и системного звука могут различаться длительности/смещение начала; объединение
дорожек в единую временную шкалу автоматически не предполагается.

Рядом с каждым WAV:

- `.txt` — исправленный текст с `[HH:MM:SS.mmm – HH:MM:SS.mmm]` у фраз;
- `.plain.txt` — тот же текст без меток, `.srt` — субтитры;
- `.asr.txt` и `.asr.json` — исходное распознавание и исходные метки;
- `.timestamps.json` — сегменты/слова, исходные и исправленные слова,
  уверенность ASR, происхождение исправления, хеш и формат аудио;
- `.segments.jsonl` — интервалы для нарезки: путь к аудио, секунды и номера
  сэмплов, текст, исходный текст, слова, session ID и признаки качества.

Версии микрофона используют одно распознавание речи, но каждый JSONL ссылается
на соответствующий WAV и его собственную частоту/хеш. Для сырого микрофона
можно нарезать шумные примеры, используя интервалы распознавания очищенной
речевой версии. Исправление слова не меняет его начало/конец. Confidence
относится к исходному ASR, а не к уверенности языковой модели в исправлении.
Редактору запрещён перенос слов между сегментами. Если текст перестал
соответствовать разметке, выставляется `needs-realignment`, новые времена
не выдумываются. Миллисекундная запись времени не означает ручную точность
границ: это оценки модели.

JSONL делит длинные фразы по границам слов до 15 секунд. `candidateForTraining`
проверяет длительность, confidence, вероятности тишины/повторов и корректность
времени. Это кандидаты с машинными псевдометками: `humanReviewed` остаётся
`false`. Сырой звук не обрезается и не заменяется. Окончательная разметка
сильной ASR-моделью/человеком может потребоваться перед обучением.

Нарезка mono 16 кГц с небольшим запасом по краям, с сохранением оригиналов:

```sh
python3 tools/export_recording_dataset.py \
  --manifest /absolute/path/record_микрофон.segments.jsonl \
  --output /absolute/path/new-dataset
```

`--manifest` можно повторять. `--labels asr` выбирает исходные метки вместо
контекстно исправленных. Экспорт создаёт `audio/`, `train.jsonl`,
`validation.jsonl`, `report.json`; разделение выполняется по сессиям и
идентичным исходным аудио, а не случайным кускам. При одной сессии отдельная
валидация не создаётся из той же записи, `readyToTrain` будет `false`.
Не передавайте все варианты одного микрофона как независимые сессии.
Формат подходит для дальнейшей подготовки разных ASR; отдельная нормализация
алфавита T-one по-прежнему нужна для латинских названий и чисел.

Для старых TXT без временных данных нужен повторный ASR по существующим WAV:

```sh
python3 tools/recording_finish.py --directory /absolute/path/to/speech-capture/SESSION --retime
```

Звуковая очистка повторно не запускается. Старые тексты и метаданные
сохраняются в `before-word-timestamps-*` внутри сессии, WAV остаются неизменными.
На двухчасовой записи это может занять существенное время. Первичный поток
слов/сегментов дополнительно пишется в `.asr-segments.jsonl` по мере получения,
чтобы при сбое долгого ASR уже полученная разметка не терялась.
Для новых записей всё создаётся автоматически; пересборка Coucou не требуется.

### Отдельный глоссарий терминов

Рабочий словарь: `~/.local/share/assistant-stack/state/speech-glossary.json`.
Он создаётся из `data/speech-glossary.json` при первом использовании. Можно
редактировать `entries` отдельно от приложения: `canonical` — английское имя,
`aliases` — варианты русского произношения/ошибок ASR, необязательный `context`
— регулярное выражение для неоднозначных слов. Например, «питон» без контекста
программирования не заменяется. Путь переопределяется через
`transcript_review.glossary_path` локальной конфигурации.

Программа ищет совпадения с токенами текущего фрагмента и соседнего контекста;
в локальную модель отправляется максимум 12 найденных записей, весь словарь
в промпт не подставляется. Уверенное соответствие из словаря имеет приоритет
над догадкой модели, в том числе при повторном использовании кеша правок.
Английское каноническое написание защищено от обратной замены моделью.
Это этап коррекции текста после ASR; модель распознавания не переобучается.

Автообучение словаря собирает фонетически близкие пары «кириллица → латиница»
из принятых правок в `candidates`. В рабочие `entries` пара попадает только
после двух независимых сессий и буквального появления английского названия
в исходном ASR. Повторная обработка и варианты дорожек одной сессии не дают
дополнительного голоса. Конфликт с другим именем блокирует автоактивацию.
Для новых имён действуют те же правила. Остальные гипотезы остаются кандидатами;
одна догадка модели не становится правилом. Сохраняются хеши ID сессий,
а не фрагменты бесед. Автоматические записи имеют `source: auto-evidence`;
это машинная разметка, а не подтверждение человеком.

Применить обновлённый глоссарий к существующему кешу правок без повторного
ASR и без вызова языковой модели:

```sh
python3 tools/recording_finish.py --directory /absolute/path/to/speech-capture/SESSION --glossary-only
```

Команда требует завершённую сессию и исходные `.asr.txt` с `.review.json`.
Она сохраняет предыдущие производные файлы в `before-glossary-*`, обновляет
аудит и, при наличии исходной временной разметки, TXT/SRT/JSON/JSONL.
Исходный ASR и аудио не меняются.
